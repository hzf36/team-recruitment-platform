## 本轮纯 UI 操作明细

### A. `[UI2]` 申请 → 撤回 → 重新申请 → 拒绝 → 查看历史

| 步骤 | 身份 | 方式 | 结果 |
|------|------|------|------|
| 发布项目 | alice | UI 发布页 | 创建 id=31，前端余 2、测试余 1 |
| 提交申请 | bob | 详情页表单 +「提交申请」 | 「申请已提交…」 |
| 撤回 | bob | 「我的申请」→「撤回」 | 状态「已撤回」，历史保留 |
| 重新申请 | bob | 详情页再次提交 | 「申请已提交…」 |
| 填写原因并拒绝 | alice | 审核区填「拒绝原因」→「拒绝」 | #40 已拒绝；原因可见；#39 已撤回仍在 |
| 查看拒绝原因与旧记录 | bob | 「我的申请」 | 见已拒绝+原因，及旧「已撤回」记录 |

### B. `[UI3]` 双页过期接受反馈

| 步骤 | 身份 | 方式 | 结果 |
|------|------|------|------|
| 发布单名额前端项目 | alice | UI | id=32，前端上限 1 |
| 两笔待审申请 | bob、carol | 各自登录后详情页提交 | 均申请「前端开发」 |
| 双开发起人页 | alice | Tab A + Tab B 同开 `/projects/32` | 两页均见 #41/#42 待审核 |
| Tab A 接受 bob | alice | 点「接受」 | bob 入成员；前端余 0 |
| Tab B **不刷新**接受 carol | alice | 点「接受」 | **明确错误「该角色名额已满」**；无虚假成功 |
| 失败申请仍可拒绝 | alice | Tab B 填原因→「拒绝」 | carol 保持待审后被拒；拒绝原因入库可见 |

真正并发一成一败仍以 **API T5** 为证；本项只验证过期页面的用户反馈。

## 第 4 轮：状态同步与响应式

### 冲突后同步（纯 UI 验证 · `[UI4]`）

| 步骤 | 结果 |
|------|------|
| Tab A 接受 bob | bob 入成员；前端剩余 0 |
| Tab B 不刷新接受 carol | 提示「该角色名额已满」 |
| 刷新后页面数据 | 角色表剩余 0；成员含 bob；carol **仍待审核**且可拒绝 |
| 错误提示 | **保留**「该角色名额已满」，不被同步清掉 |
